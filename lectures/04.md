# 流密码 Stream Cipher

<p class="lead">一次一密是完美保密的，但密钥和消息一样长。流密码换了个思路：只共享一个短种子，用确定性算法把它“拉长”成一条看起来随机的密钥流，再与明文异或。本讲先说清流密码与 PRG 的关系、用流密码加密的两种工作模式，再拆解线性反馈移位寄存器（LFSR）为什么会被 2n 个输出位彻底攻破，最后看引入非线性的 RC4，以及 RC4 在 WEP 中是怎样被攻破的。</p>

## 4.1 什么是流密码

**流密码**<span class="en">Stream Cipher</span>是什么？用来做什么？<Src p="5" />

- 它是一个**确定性算法**，把一个短的随机**种子**（seed）扩展成一串“看起来随机”的比特流；
- 作为一种**密码原语**使用：可以用来实例化 PRG、加密消息……
- **优点**：效率高；**缺点**：<span class="hl">没有严格的安全性证明</span>。

<Fig src="/img/04/p005.jpg" size="md" cap="流密码：输入短种子（钥匙 101010），输出长比特流 011011001110011……" p="5" />

::: def 流密码的形式化定义 @P6
流密码是**一对确定性算法** $(\mathsf{Init}, \mathsf{GetBits})$：

- **Init**：$st_0 := \mathsf{Init}(s, [IV])$；
- **GetBits**：$(y_i, st_i) := \mathsf{GetBits}(st_{i-1})$，$i = 1, 2, \dots$

其中：

1. $st_0, st_1, \dots$ 是**状态信息**（state）；
2. Init 是**初始化算法**：输入种子 $s$ 和一个可选的**初始化向量** $IV$（Initialization Vector），输出初始状态 $st_0$；
3. GetBits 输入当前状态 $st_{i-1}$，输出一个比特 $y_i$ 和新状态 $st_i$；
4. 输出的比特流 $y_1, y_2, \dots$ 常被称为**密钥流**<span class="en">keystream</span>（因为它通常与明文异或来生成密文）；
5. 实际中 $y_i$ 往往是**一块比特**（如 RC4 每次输出一个字节）而不是一个比特。
:::

::: ex [理解] 流密码 = 一台“有记忆”的状态机
Init 只在开头调用一次，负责把种子（和 IV）“装进”内部状态；之后每调用一次 GetBits，状态机就**更新一次状态**并**吐出一段输出**。安全性的全部希望在于：只看输出，猜不出内部状态，也就预测不了下一位。4.5–4.7 节会看到，LFSR 正是在这一点上失败的。<span class="muted">（补充说明）</span>
:::

::: tldr
流密码 = Init（种子 → 初始状态）+ GetBits（状态 → 输出 + 新状态），输出称为密钥流；高效，但没有严格证明。
:::

## 4.2 用流密码实例化 PRG

给定一个流密码和任意想要的**扩展因子** $\ell$，就能用下面的算法实现一个 PRG <Src p="8" />：

```text
算法 1  用流密码实例化 PRG                                   （P8）
输入：种子 s，可选的初始化向量 IV
输出：y_1, …, y_ℓ
1: st_0 := Init(s, IV)
2: for i = 1 to ℓ do
3:     (y_i, st_i) := GetBits(st_{i-1})
4: return y_1, …, y_ℓ
```

::: ex [补充说明] “安全的流密码”该怎么理解
按照教材（Katz–Lindell）的说法：若对任意多项式 $\ell$，上面算法得到的 $G_\ell(s) = y_1\cdots y_\ell$（不带 IV 时）都是一个**伪随机生成器**——即没有多项式时间敌手能以不可忽略的优势区分 $G_\ell(s)$（$s$ 均匀）与 $\ell$ 位均匀随机串——就称这个流密码是**安全的**。带 IV 时要求更强：对同一个 $s$、多个不同的 $IV$，各条输出合在一起仍要像独立的随机串（$IV \mapsto$ 输出 应像一个伪随机函数）。这正是 4.4 节“非同步模式”所依赖的性质。

课件强调“没有严格证明”的意思是：实际使用的流密码（RC4、Trivium、ZUC……）都**无法从困难问题归约证明**其满足上述定义，只能靠长期的密码分析建立信心。
:::

::: exam 与期中考点的关联
2025 期中 Q3 给定一个 PRG $G$，判断 $G'(s)=G(s_1\cdots s_{|s|-1})\|s_{|s|}$、$G'(s)=G(s\oplus 1^{|s|})$ 等构造是否仍是 PRG——这正是“把流密码当 PRG 用”时需要的思维方式：**输出必须对任何多项式时间区分器都不可区分**，只要能构造出一个区分器（比如“第一位总是 0”），就不是 PRG。
:::

::: tldr
流密码跑 $\ell$ 次 GetBits 就是一个扩展因子为 $\ell$ 的 PRG；“流密码安全”就是指这样得到的 $G_\ell$ 是伪随机的。
:::

## 4.3 基本做法：明文 ⊕ 密钥流

加密就是把**明文和密钥流按位异或** <Src p="11" />：$c_i = m_i \oplus y_i$，解密同样是 $m_i = c_i \oplus y_i$。

<Fig src="/img/04/p011.jpg" size="sm" cap="一个例子：WiFi 网络的 WEP 用名为 RC4 的流密码加密消息——种子 = IV + key，RC4 密钥流 0101 ⊕ 明文 1100 = 密文 1001（图自 Wikipedia）" p="11 · P46" />

**优点**：效率很高、硬件实现简单、容易处理任意长度的消息……

**缺点**：

1. <span class="hl">不能用同一个密钥（或同一段密钥流）加密不同的明文</span>，否则明文之间的相关性会轻易地在对应密文中暴露出来；
2. <span class="hl">易受比特翻转攻击</span><span class="en">bit-flipping attack</span>，因此往往还需要做消息完整性校验（后续课程会讲）。

下面把这三件事（正确性 + 两个缺点）都严格写出来。<span class="muted">（补充说明）</span>

::: def [命题] 解密的正确性
设密钥流为 $y = y_1y_2\cdots y_\ell$，$c = m \oplus y$，则 $c \oplus y = m$。

**证明**：对每一位 $i$，

$$
c_i \oplus y_i = (m_i \oplus y_i) \oplus y_i = m_i \oplus (y_i \oplus y_i) = m_i \oplus 0 = m_i .
$$

逐步依据：第一个等号代入 $c_i$ 的定义；第二个等号用异或的**结合律**；第三个等号用 $a \oplus a = 0$；第四个等号用 $a \oplus 0 = a$。接收方与发送方用同一个种子（和 IV）运行同一个确定性算法，所以得到同一条 $y$，正确性成立。
:::

::: warn [缺点 1] 密钥流重用 ⇒ 两段密文异或即得两段明文的异或
若用同一段密钥流 $y$ 加密了 $m_1, m_2$（等长），则

$$
c_1 \oplus c_2 = (m_1 \oplus y) \oplus (m_2 \oplus y) = (m_1 \oplus m_2) \oplus (y \oplus y) = m_1 \oplus m_2 .
$$

依据：第一步代入定义；第二步用异或的交换律与结合律重新组合；第三步用 $y \oplus y = 0^\ell$ 与 $a \oplus 0^\ell = a$。

于是敌手**不需要密钥**就拿到了 $m_1 \oplus m_2$：一旦知道（或猜中）$m_1$ 的某一段，立即得到 $m_2$ 的对应段；自然语言的冗余足以让“拖动猜词”把两条消息都还原出来。这和“一次一密的密钥只能用一次”是同一回事。
:::

::: warn [缺点 2] 比特翻转：密文的可延展性
敌手截获 $c = m \oplus y$，选任意 $\Delta$，发送 $c' = c \oplus \Delta$。接收方解密得

$$
c' \oplus y = (m \oplus y \oplus \Delta) \oplus y = m \oplus \Delta .
$$

即：**翻转密文的第 $i$ 位，明文的第 $i$ 位就跟着翻转**，而且敌手全程不需要密钥。若敌手知道报文格式（如金额字段在哪里、原值是多少），就能把它精确地改成任意值。加密只提供保密性，不提供完整性——这呼应了第 0 讲的“保密性 ≠ 完整性”。
:::

<L04Reuse />

::: tldr
流密码加密 = 明文 ⊕ 密钥流。密钥流一旦重用，$c_1\oplus c_2=m_1\oplus m_2$；密文翻一位，明文就翻一位——前者要靠“绝不重用”，后者要靠完整性校验。
:::

## 4.4 工作模式：同步与非同步

实际中，用流密码加密有两种**工作模式**<span class="en">modes of operation</span> <Src p="13" />：

<Fig src="/img/04/p013a.jpg" cap="同步模式（Synchronized Mode）：k 经 G 生成一条长密钥流，依次切成 Part 1、Part 2、Part 3，分别与 m₁、m₂、m₃ 异或得到 c₁、c₂、c₃" p="13" />

<Fig src="/img/04/p013b.jpg" cap="非同步模式（Unsynchronized Mode）：每条消息用同一个 k 和各自不同的 IVᵢ 重新调用 G，得到独立的一段密钥流" p="13" />

| | 同步模式 | 非同步模式 |
|---|---|---|
| 密钥流来源 | 一次 $\mathsf{Init}(k)$，之后不断调用 GetBits，各消息依次使用**互不重叠**的片段 | 每条消息 $\mathsf{Init}(k, IV_i)$，各自生成一段密钥流 |
| 需要的状态 | 双方都要**保存状态**（用到了哪里），并保持同步 | **无状态**：每条消息独立处理 |
| 额外传输 | 无 | 每条密文都要附上 $IV_i$（IV 不需要保密） |
| 对 G 的要求 | $G_\ell(k)$ 是 PRG 即可 | 更强：同一 $k$、不同 $IV$ 的输出要像相互独立的随机串 |
| 典型场景 | 一次会话中连续、可靠、有序地传输 | 丢包、乱序常见的网络（如 WEP 的每个数据帧） |

<span class="muted">（表格为补充说明，归纳自课件 P13 的两张图。）</span>

<L04Modes />

::: tldr
同步模式：一条长密钥流按顺序切片，双方要保持同步；非同步模式：每条消息配一个新 IV，无状态但要传 IV，而且 IV 绝不能重复。
:::

## 4.5 线性反馈移位寄存器

::: def 线性反馈移位寄存器 Linear-Feedback Shift Register (LFSR) @P16
一个 **$n$ 阶**（degree-$n$）LFSR 由以下两部分定义：

- $n$ 个 1 比特寄存器构成的数组：$s_{n-1}, \dots, s_0$；
- $n$ 个**反馈系数**：$c_{n-1}, \dots, c_0 \in \{0,1\}$。

并且：

- 它的（当前）**状态**是所有寄存器中比特的集合；
- 时刻 $t$ 之后的下一个状态由下式决定：

$$
\begin{aligned}
\text{移位（Shift）：}\quad & s_i^{(t+1)} := s_{i+1}^{(t)}, \qquad i = 0, \dots, n-2;\\
\text{线性反馈（Linear-feedback）：}\quad & s_{n-1}^{(t+1)} := \bigoplus_{i=0}^{n-1} c_i\, s_i^{(t)};
\end{aligned}
$$

- 它的**输出**是比特序列 $s_0^{(0)}, s_0^{(1)}, \dots$
:::

### 4.5.1 例：一个 4 阶 LFSR

图 3 是一个反馈系数为 $(c_3, c_2, c_1, c_0) = (0,1,0,1)$ 的 4 阶 LFSR <Src p="17–26" />：只有 $s_2$ 和 $s_0$ 被抽头参与异或，异或结果写回最左边的 $s_3$，$s_0$ 从右边移出作为输出。

<Fig src="/img/04/p017.jpg" size="md" cap="图 3：反馈系数为 0,1,0,1 的 4 阶 LFSR" p="17–26" />

给定初始状态 $(s_3, s_2, s_1, s_0) = (0,0,1,1)$，逐拍计算（反馈位 $= c_2 s_2 \oplus c_0 s_0 = s_2 \oplus s_0$）：

| 时刻 $t$ | 状态 $(s_3,s_2,s_1,s_0)$ | 反馈位 $s_2 \oplus s_0$ | 本拍输出 $s_0$ |
|---|---|---|---|
| 0 | (0, 0, 1, 1) | $0 \oplus 1 = 1$ | 1 |
| 1 | (1, 0, 0, 1) | $0 \oplus 1 = 1$ | 1 |
| 2 | (1, 1, 0, 0) | $1 \oplus 0 = 1$ | 0 |
| 3 | (1, 1, 1, 0) | $1 \oplus 0 = 1$ | 0 |
| 4 | (1, 1, 1, 1) | $1 \oplus 1 = 0$ | 1 |
| 5 | (0, 1, 1, 1) | $1 \oplus 1 = 0$ | 1 |
| 6 | (0, 0, 1, 1) ← 回到 $t=0$ | 1 | 1 |
| 7 | (1, 0, 0, 1) | 1 | 1 |
| … | … | … | … |

所以后续状态依次为 $(1,0,0,1), (1,1,0,0), (1,1,1,0), (1,1,1,1), (0,1,1,1), (0,0,1,1), (1,0,0,1), \dots$，输出为 $1,1,0,0,1,1,1,1,\dots$

<span class="muted">（补充说明：从表中可见这个 LFSR 的周期只有 6——第 6 拍回到了初始状态，之后输出以 110011 为周期循环。）</span>

### 4.5.2 几点安全性分析

::: qa 这个 4 阶 LFSR 能输出无限长的“随机比特”流吗？ @P27–28
不能。输出至多 $2^4$ 个比特之后，比特流就一定会**重复自身**。
:::

::: qa 那 $n$ 阶 LFSR 呢？ @P29–30
输出至多 $2^n$ 个比特之后就开始产生重复的比特。
:::

::: def [证明] 为什么 $n$ 阶 LFSR 至多 $2^n$ 拍就开始重复
**命题**：任意 $n$ 阶 LFSR 的状态序列 $st_0, st_1, \dots$ 中，存在 $0 \le \mu < \mu + \lambda \le 2^n$ 使得 $st_{\mu} = st_{\mu+\lambda}$，并且此后输出以 $\lambda$ 为周期循环。

**证明**：

1. 状态是 $n$ 个比特，所以**所有可能的状态只有 $2^n$ 个**。
2. 看前 $2^n + 1$ 个状态 $st_0, \dots, st_{2^n}$：$2^n+1$ 个对象放进 $2^n$ 个“格子”，由**鸽巢原理**必有两个相同，记为 $st_\mu = st_{\mu+\lambda}$，$\lambda \ge 1$，$\mu + \lambda \le 2^n$。
3. 下一状态**只由当前状态决定**（定义中的移位与反馈都是当前状态的确定函数），所以由 $st_\mu = st_{\mu+\lambda}$ 归纳得 $st_{\mu+k} = st_{\mu+\lambda+k}$ 对所有 $k \ge 0$ 成立。
4. 输出 $y_{t+1} = s_0^{(t)}$ 是状态的函数，因此从第 $\mu+1$ 个输出起，输出序列以 $\lambda$ 为周期，即至多输出 $2^n$ 位后开始重复。$\blacksquare$

**更紧的界**<span class="muted">（补充说明）</span>：全 0 状态经过移位和异或仍是全 0，一旦进入就永远输出 0；所以“有用”的 LFSR 只在 $2^n - 1$ 个非零状态之间循环，周期至多 $2^n - 1$。此外，若 $c_0 = 1$，状态转移是可逆的（由 $st_{t+1}$ 可唯一反推 $st_t$：$s_0^{(t)} = s_{n-1}^{(t+1)} \oplus \bigoplus_{i\ge1} c_i s_{i-1}^{(t+1)}$），此时 $\mu = 0$，序列从一开始就是纯周期的；若 $c_0 = 0$，可能先走若干拍“尾巴”再进入循环（在上面的演示里把 $c_0$ 关掉试试）。
:::

::: qa 当 $n$ 很大，比如 $n = 128$ 时，$n$ 阶 LFSR 可以用于密码学吗？ @P31–32
不能。即使我们知道怎样把它做成 $n$ 阶的**最大长度 LFSR**（maximal-length LFSR）——即在开始重复之前遍历全部 $2^n$ 个状态的 LFSR——也不行。

一般而言，“**LFSR 不适合用于密码学**”。

<span class="muted">（注：严格说，最大长度 LFSR 遍历的是全部 $2^n - 1$ 个**非零**状态，全 0 状态是一个孤立的不动点，见上面的证明。理由见下一节：周期再长也挡不住重构攻击。）</span>
:::

::: tldr
$n$ 阶 LFSR = $n$ 个寄存器右移 + 抽头异或回填；状态有限，周期 ≤ $2^n-1$。但周期长 ≠ 安全。
:::

## 4.6 LFSR 的重构攻击

一般而言 LFSR 不适合密码学用途 <Src p="34" />：由于其**内部的线性性**，LFSR 容易受到**重构攻击**<span class="en">reconstruction attack</span>——敌手观察到 $n$ 阶 LFSR 的 **$2n$ 个输出位**之后，就能重构它的全部状态。

### 4.6.1 为什么 2n 位就够：两条引理

<span class="muted">（以下推导为补充说明，把课件例子背后的一般方法写完整。记输出 $y_{t+1} := s_0^{(t)}$，$t = 0,1,\dots$）</span>

::: def [引理 1] 前 n 个输出就是初始状态
对 $0 \le i \le n-1$ 及任意 $t \ge 0$，有 $s_i^{(t)} = s_0^{(t+i)} = y_{t+i+1}$。特别地 $(s_{n-1}^{(0)}, \dots, s_0^{(0)}) = (y_n, \dots, y_1)$。

**证明**：对 $i$ 归纳。$i = 0$ 时 $s_0^{(t)} = s_0^{(t+0)}$ 平凡成立。设对 $i-1$（$1 \le i \le n-1$）成立，则由**移位规则** $s_{i-1}^{(t+1)} = s_i^{(t)}$（因为 $i-1 \le n-2$），

$$
s_i^{(t)} = s_{i-1}^{(t+1)} \overset{\text{归纳假设}}{=} s_0^{(t+1+i-1)} = s_0^{(t+i)} .
$$

最后由输出的定义 $s_0^{(t+i)} = y_{t+i+1}$。$\blacksquare$
:::

::: def [引理 2] 输出满足线性递推
对任意 $t \ge 0$：$\displaystyle y_{t+n+1} = \bigoplus_{i=0}^{n-1} c_i\, y_{t+i+1}$。

**证明**：

$$
y_{t+n+1} \overset{\text{引理 1}}{=} s_{n-1}^{(t+1)} \overset{\text{反馈规则}}{=} \bigoplus_{i=0}^{n-1} c_i\, s_i^{(t)} \overset{\text{引理 1}}{=} \bigoplus_{i=0}^{n-1} c_i\, y_{t+i+1} .
$$

第一步取引理 1 中 $i = n-1$、时刻 $t+1$；第二步是 LFSR 的线性反馈定义；第三步对每个 $s_i^{(t)}$ 再用一次引理 1。$\blacksquare$
:::

于是攻击分两步：

1. **初始状态**：由引理 1，直接读 $y_1, \dots, y_n$；
2. **反馈系数**：对 $t = 0, \dots, n-1$ 写出引理 2，得到 $n$ 个关于未知数 $c_{n-1}, \dots, c_0$ 的 **GF(2) 上的线性方程**，系数矩阵的第 $t$ 行恰好是 $t$ 时刻的状态。这只用到 $y_1, \dots, y_{2n}$——正好 $2n$ 位。用高斯消元（模 2）解出 $c_i$，就得到整个 LFSR，之后的所有输出都能预测。

### 4.6.2 课件例子

::: ex [例] 从 8 个输出位恢复 4 阶 LFSR @P35–36
敌手观察到某个 4 阶 LFSR 的 8 个连续输出位：$1, 1, 0, 0, 1, 1, 1, 1$。

要重构这个 LFSR，敌手需要知道 $(s_3^{(0)}, s_2^{(0)}, s_1^{(0)}, s_0^{(0)})$ 和 $(c_3, c_2, c_1, c_0)$。

- 敌手知道 $(s_3^{(0)}, s_2^{(0)}, s_1^{(0)}, s_0^{(0)}) = (0, 0, 1, 1)$（前 4 位倒过来读）。
- 敌手可以通过求解 **4 个未知数的 4 个线性方程**计算 $(c_3, c_2, c_1, c_0)$：

$$
\begin{aligned}
1 &= c_3 \cdot 0 \oplus c_2 \cdot 0 \oplus c_1 \cdot 1 \oplus c_0 \cdot 1 && (1)\\
1 &= c_3 \cdot 1 \oplus c_2 \cdot 0 \oplus c_1 \cdot 0 \oplus c_0 \cdot 1 && (2)\\
1 &= c_3 \cdot 1 \oplus c_2 \cdot 1 \oplus c_1 \cdot 0 \oplus c_0 \cdot 0 && (3)\\
1 &= c_3 \cdot 1 \oplus c_2 \cdot 1 \oplus c_1 \cdot 1 \oplus c_0 \cdot 0 && (4)
\end{aligned}
$$

解 (1)–(4) 得 $(c_3, c_2, c_1, c_0) = (0, 1, 0, 1)$。

**求解过程**<span class="muted">（补充说明）</span>：方程 (1)–(4) 化简为 $c_1 \oplus c_0 = 1$、$c_3 \oplus c_0 = 1$、$c_3 \oplus c_2 = 1$、$c_3 \oplus c_2 \oplus c_1 = 1$。

- (4) ⊕ (3)：$c_1 = 1 \oplus 1 = 0$；
- 代入 (1)：$c_0 = 1 \oplus c_1 = 1$；
- 代入 (2)：$c_3 = 1 \oplus c_0 = 0$；
- 代入 (3)：$c_2 = 1 \oplus c_3 = 1$。

与 4.5.1 节例子的真实抽头完全一致；方程 (1)–(4) 的系数行正是表中 $t=0,1,2,3$ 的状态，右端是 $y_5, \dots, y_8$。
:::

<L04LfsrAttack />

::: warn [细节] 方程组不一定满秩
若这 $n$ 个状态向量线性相关（例如输出序列本身周期很短，或“线性复杂度”小于 $n$），方程组会有多个解。此时任取一个解也能正确预测后续输出（两个 $n$ 阶 LFSR 在前 $2n$ 位一致，则整个序列都一致），对攻击者没有影响。一般情形下用 **Berlekamp–Massey 算法**可以在不知道 $n$ 的情况下，用 $2L$ 位输出求出最短的生成 LFSR（$L$ 为线性复杂度）。<span class="muted">（补充说明）</span>
:::

::: exam 可能的考法
给定反馈系数与初始状态，写出若干拍的状态和输出、求周期；或者给定 $2n$ 个输出位，列出线性方程组并解出反馈系数（务必注意：**前 $n$ 位倒过来读就是初态**、**方程系数行就是各时刻的状态**）。
:::

::: tldr
LFSR 的每一位输出都是前 $n$ 位的线性组合：看到 $2n$ 位 → 前 $n$ 位给出初态、后 $n$ 位给出 $n$ 个线性方程 → 高斯消元解出抽头 → 全部未来输出可预测。
:::

## 4.7 引入非线性

为了挫败重构攻击，可以在 **GetBits** 函数中**引入非线性** <Src p="38" />。具体来说，非线性可以加在：

1. **状态更新**过程中，或
2. **比特生成**过程中，或
3. 两者都加。

例子包括 RC4、Trivium 等。

<Fig src="/img/04/p038.jpg" size="md" cap="图 4：流密码的 GetBits 算法负责 1) 更新状态、2) 由当前状态生成输出比特" p="38" />

::: ex [补充说明] 三种做法的典型代表
- **非线性输出（滤波生成器）**：状态仍用 LFSR 更新，但输出取若干寄存器的非线性函数（如 AND）；
- **非线性组合（组合生成器）**：几个 LFSR 并行，用非线性函数合成一位输出；
- **非线性状态更新**：如 Trivium 的反馈里含 AND 项、RC4 的状态是一个依赖数据不断交换的置换。

一旦有了非线性，“输出 = 状态的线性函数”不再成立，4.6 节的线性方程组就列不出来了。
:::

::: tldr
LFSR 的软肋是线性；在状态更新或输出生成中引入非线性（RC4、Trivium……），重构攻击就失效了。
:::

## 4.8 RC4

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 200px;gap:18px;align-items:center">
<div>

**RC4**（Rivest Cipher 4，也称 ARC4 或 ARCFOUR，意为 Alleged RC4）是一个著名的流密码 <Src p="40" />：

- 由 Ron Rivest 于 **1987** 年设计；
- 软硬件实现都很高效；
- 至今仍被广泛使用，例如 WiFi 网络的有线等效保密（WEP），以及 TLS/SSL 协议；
- 近期研究表明它有严重的密码学弱点（即**统计偏差**），<span class="hl">不应再使用</span> [4]。

</div>
<Fig src="/img/04/p040.jpg" cap="图 5：R. Rivest，RSA 算法的共同发明人，2002 年图灵奖得主" p="40" />
</div>

### 4.8.1 Init 算法（KSA）

Init 算法输出数组 $S = (0, 1, \dots, 255)$ 的一个**置换** <Src p="41" />。<span class="muted">（课件写作 $S = (1, 2, \dots, 255)$，应为 $0$ 到 $255$ 共 256 个元素，见图 6(a)。）</span>

<Fig src="/img/04/p041.jpg" cap="图 6：RC4 的 Init 算法。(a) S 与 T 的初始状态：S[i] = i，T 由密钥 K 循环重复填满；(b) S 的初始置换：j = j + S[i] + T[i]，交换 S[i] 与 S[j]（图自 W. Stallings《Cryptography and Network Security》）" p="41" />

```text
算法 2  RC4 的 Init 算法（所有加法均 mod 256）                  （P42）
输入：16 字节密钥 k
输出：初始状态 (S, i, j)
for i = 0 to 255:
    S[i] := i
    T[i] := k[i mod 16]
j := 0
for i = 0 to 255:
    j := j + S[i] + T[i]
    交换 S[i] 与 S[j]
i := 0, j := 0
return (S, i, j)
```

<span class="muted">（注：课件按 16 字节密钥书写；RC4 实际支持 1–256 字节的变长密钥（图 6 中的 Keylen），一般写作 T[i] := k[i mod keylen]。下面的演示按变长密钥实现。）</span>

### 4.8.2 GetBits 算法（PRGA）

每个时钟节拍，GetBits 算法输出置换后数组 $S$ 中的**一个元素**，并通过**交换两个元素**对数组重新置换 <Src p="43" />。

<Fig src="/img/04/p043.jpg" cap="图 7：RC4 的 GetBits 算法（(c) 流生成）：j = j + S[i]，交换 S[i] 与 S[j]，t = S[i] + S[j]，输出 S[t]（图自 W. Stallings）" p="43" />

```text
算法 3  RC4 的 GetBits 算法（所有加法均 mod 256）               （P44）
输入：当前状态 (S, i, j)
输出：输出字节 y；更新后的状态 (S, i, j)
i := i + 1
j := j + S[i]
交换 S[i] 与 S[j]
t := S[i] + S[j]
y := S[t]
return (S, i, j), y
```

<L04Rc4 />

::: def [命题] S 始终是 {0,…,255} 的一个置换
**证明**（对执行步数归纳，补充说明）：初始化后 $S[i] = i$，显然是置换。KSA 和 PRGA 对 $S$ 的**唯一修改**是“交换 $S[i]$ 与 $S[j]$”；若交换前 $S$ 是置换（每个值恰好出现一次），交换只改变两个值的位置、不改变值的多重集合，交换后每个值仍恰好出现一次。由归纳，任何时刻 $S$ 都是置换。因此 RC4 的内部状态可以看作“一个 256 元置换 + 两个下标 $i, j$”，约 $\log_2(256!) + 16 \approx 1700$ 比特。
:::

::: ex [补充说明] RC4 的非线性在哪里
$j$ 的更新用到了 $S[i]$，输出用到了 $S[S[i] + S[j]]$——**下标本身依赖数据**（查表套查表），这在 GF(2) 上远不是线性的，所以 4.6 节的方程组方法不适用。但 RC4 的输出存在**统计偏差**：例如第 2 个输出字节为 0 的概率约为 $2/256$，是理想值的 2 倍（Mantin–Shamir, 2001）；利用这类偏差，RC4 在 WPA-TKIP 和 TLS 中都被实际攻破（课件参考文献 [4]）。2015 年 RFC 7465 已禁止在 TLS 中使用 RC4。
:::

::: tldr
RC4 = KSA（用密钥把恒等置换 S 打乱 256 次）+ PRGA（每拍 $i{+}{+}$、$j \mathrel{+}= S[i]$、交换、输出 $S[S[i]+S[j]]$）。简单高效，但有统计偏差，已不应使用。
:::

## 4.9 攻击基于 RC4 的 WEP

**WiFi 中的 WEP** <Src p="46" />：

- WiFi 网络的**有线等效保密**<span class="en">Wired Equivalent Privacy, WEP</span>协议用 RC4 保证消息的保密性，用 **CRC-32** 做正确性校验；
- 标准的 64 位 WEP 使用 **40 位密钥**（10 个十六进制字符 0–9、A–F）和 **24 位 IV**；
- 两个 WEP 用户先共享同一个密钥，然后用**不同的 IV** 加密不同的消息，以避免在加密中使用相同的密钥流。

<span class="muted">课件 P46 的图 8（WEP 加密示意，图自 Wikipedia）与 P11 是同一张图，见 4.3 节：种子 = IV ‖ key，RC4 密钥流与明文异或。</span>

### 4.9.1 WEP 的短 IV 缺陷

::: warn WEP 的短 IV 缺陷 The short IV flaw @P47
- IV 总共只有 $2^{24}$ 种可能；
- 一个繁忙的接入点（例如以 11 Mbps 持续发送 1500 字节的数据包）大约 **5 小时**就会用完所有 IV：

$$
\frac{2^{24} \times 1500 \times 8}{11 \times 10^{6}} \approx 5\ \text{小时};
$$

- 此后就开始出现**重复的密钥流**；
- 已建议用户**永远不要使用 WEP**（几分钟就能被攻破）；
- 尽管 **WPA**（Wi-Fi Protected Access）以更安全的方式使用 RC4，由于 RC4 已被证明不安全，现在也建议用户放弃 WPA。
:::

**算式拆解**<span class="muted">（补充说明）</span>：每个包 $1500 \times 8 = 12000$ 比特，每秒可发 $11\times10^6 / 12000 \approx 916.7$ 个包；$2^{24} = 16\,777\,216$ 个 IV 需要 $16\,777\,216 / 916.7 \approx 18\,302$ 秒 $\approx 5.08$ 小时。

**更糟的是生日悖论**<span class="muted">（补充说明）</span>：如果 IV 是随机选取的，不必等到 $2^{24}$ 个全部用完——大约 $\sqrt{\pi/2 \cdot 2^{24}} \approx 5134$ 个包后就期望出现第一次 IV 重复，在上面的场景下只需几秒。一旦 IV 重复，就回到了 4.3 节的“密钥流重用”：$c_1 \oplus c_2 = m_1 \oplus m_2$。再加上 CRC-32 是**线性**的（$\mathrm{CRC}(m \oplus \Delta) = \mathrm{CRC}(m) \oplus \mathrm{CRC}(\Delta) \oplus \mathrm{CRC}(0)$），敌手做比特翻转时可以同时把校验值改对，完整性校验形同虚设。实际中最致命的是 Fluhrer–Mantin–Shamir（2001）的**相关密钥攻击**：WEP 的种子是“IV ‖ 密钥”，IV 公开，RC4 前几个输出字节与密钥字节的相关性让敌手收集足够多的包后直接恢复密钥。

<L04WepIv />

### 4.9.2 WEP、WPA、WPA2、WPA3

为了 WiFi 安全，现在建议用户使用 **WPA2 或 WPA3** <Src p="48" />。WPA2 和 WPA3 使用**分组密码 AES** 加密，并采用了其他安全措施。

<Fig src="/img/04/p048.webp" size="md" cap="图 9：路由器中的安全选项：None / WEP / WPA-PSK (TKIP) / WPA2-PSK (AES) / 混合模式（图自 kbnetgearrouter.net）" p="48" />

::: qa 路由器设置里该选哪一项？
选 **WPA2-PSK (AES)**（或支持时选 WPA3）。None 不加密；WEP 几分钟可破；WPA-PSK (TKIP) 仍基于 RC4，已建议放弃；混合模式为了兼容旧设备会保留 TKIP。<span class="muted">（补充说明，基于课件 P47–48 的结论）</span>
:::

::: tldr
WEP = RC4(IV‖key) + CRC-32，IV 只有 24 位：几小时必然重复（随机 IV 几秒就撞），密钥流重用 + 线性校验 + RC4 弱点 → 几分钟破解。请用 WPA2/WPA3（AES）。
:::

## 4.10 使用流密码的两条建议

::: prin 建议 1：停止使用不安全的流密码 @P50–51
<Fig src="/img/04/p050.jpg" cap="图 10：流密码对比表（表自 Wikipedia “Stream cipher”）。列依次为：流密码、提出时间、速度（每字节周期数）、有效密钥长度、内部状态、已知最佳攻击及其计算复杂度。如 RC4（1987，状态 2064 位，Shamir 初始字节密钥推导或已知明文攻击，2¹³ 或 2³³）、Trivium（80 位密钥、288 位状态，最佳攻击仍是暴力 2¹³⁵）、WAKE（CPA & CCA，不安全）" p="50" />

一些推荐使用的流密码 <Src p="51" />：

- **ZUC-128/256**（“祖冲之流密码”），国家密码管理局（2012 至今），用于 4G/5G 系统 [7]；
- **Enocoro-80/128**、**Trivium-80**，ISO/IEC 29192 标准（2012 至今）；
- **Grain-128AEAD** 是 NIST 轻量级密码竞赛决赛圈中的流密码（<s>仍在评审中，2021 至今</s>，课件更新为：2025 年已最终定稿！）。感兴趣可阅读 billatnapier.medium.com 上的文章 “After AES, NIST is defining the next great standard for encryption: lightweight cryptography”。

<span class="muted">（注：NIST 轻量级密码竞赛于 2023 年宣布的胜者是 **Ascon**，并于 2025 年 8 月以 SP 800-232 正式发布；Grain-128AEAD 是十个决赛算法之一，但不是最终胜者。课件此处的“finalized winner in 2025”指竞赛在 2025 年定稿，并非 Grain-128AEAD 胜出。）</span>
:::

::: prin 建议 2：私钥加密中，分组密码通常优于流密码 @P52
在私钥加密中，为了更好的安全性，**分组密码**<span class="en">block cipher</span>一般比流密码更可取。

<span class="muted">补充说明：分组密码（如 AES）经过了长期、公开、充分的分析，并且可以通过 CTR 等工作模式“当作流密码使用”，同时享受分组密码的安全性；后续讲的 PRF/PRP 理论也正是围绕分组密码展开的。</span>
:::

::: tldr
别再用 RC4、WEP 这类已被攻破的设计；需要流密码时选 ZUC、Trivium、Grain 等现行标准；私钥加密优先考虑分组密码（AES）。
:::

::: card 流密码
- (Init, GetBits) 两个确定性算法
- $st_0=\mathsf{Init}(s,[IV])$，$(y_i,st_i)=\mathsf{GetBits}(st_{i-1})$
- 跑 $\ell$ 次即扩展因子 $\ell$ 的 PRG
- 高效，但无严格证明
:::
::: card 加密与两大软肋
- $c = m \oplus y$，$c\oplus y=m$
- 密钥流重用：$c_1\oplus c_2=m_1\oplus m_2$
- 比特翻转：$c\oplus\Delta \mapsto m\oplus\Delta$，需完整性校验
:::
::: card 工作模式
- 同步：一条长流顺序切片，双方保持状态
- 非同步：每条消息新 IV，IV 随密文发送
- IV 重复 ⇒ 密钥流重复
:::
::: card LFSR
- 右移 + $s_{n-1}' = \bigoplus c_i s_i$，输出 $s_0$
- 周期 ≤ $2^n-1$（全 0 不动）
- 最大长度 LFSR 也不安全
:::
::: card 重构攻击
- 前 $n$ 位输出（倒读）= 初态
- $y_{t+n+1}=\bigoplus c_i y_{t+i+1}$：$n$ 个线性方程
- 2n 位输出 → 高斯消元 → 抽头
:::
::: card RC4 与 WEP
- KSA：$j \mathrel{+}= S[i]+T[i]$，交换
- PRGA：$i{+}{+}$，$j \mathrel{+}= S[i]$，交换，输出 $S[S[i]+S[j]]$
- WEP：24 位 IV ≈ 5 小时用尽，几分钟可破
