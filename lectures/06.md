## 6.1 什么是分组密码？

先看两本书给的通俗说法 <Src p="5" />：

- “一种把数据切成小块、再逐块加密的算法。”——《Cryptography for Dummies》（Chey Cobb）
- “一种针对**固定长度**数据块的加密函数。”——《Cryptography Engineering》（N. Ferguson 等）

<FigGrid>
<Fig src="/img/06/p005a.jpg" size="sm" cap="Cryptography for Dummies" p="5" />
<Fig src="/img/06/p005b.jpg" size="sm" cap="Cryptography Engineering" p="5" />
</FigGrid>

本课采用教材的定义，它比上面两种说法都精确：

::: def 分组密码 Block Cipher（又称“块密码”） @P6
分组密码是一个**高效的、带密钥的置换**（efficient, keyed permutation）：

$$F:\ \{0,1\}^n \times \{0,1\}^{\ell} \to \{0,1\}^{\ell}.$$

- **高效**：给定 $k$，$F_k(x) \overset{\text{def}}{=} F(k,x)$ 及其逆 $F_k^{-1}$ 都能在多项式时间内计算；
- **置换**：每个 $F_k$ 都是双射（一一对应）；
- $n$ 称为**密钥长度** <span class="en">key length</span>，$\ell$ 称为**分组长度** <span class="en">block length</span>。

本质上，分组密码**就是一个带密钥的置换函数**。
:::

::: def 对分组密码的安全期望 @P7
- **理论上**：我们希望分组密码的行为至少像一个（强）伪随机置换 <span class="en">(strong) pseudorandom permutation</span>；
- **实践中**：一个“好”的分组密码，已知最好的攻击的时间复杂度应当 $\approx 2^n$，即与穷举密钥（暴力搜索）相当。

<span class="muted">（课件原文 “brutal-force” 应为 brute-force。）</span>
:::

::: ex [补充说明] 什么是“强”伪随机置换
普通的伪随机置换（PRP）只要求：敌手拿到 $F_k(\cdot)$ 的预言机时，无法把它和一个真正随机的置换区分开。**强** PRP 还允许敌手同时访问逆预言机 $F_k^{-1}(\cdot)$，仍然区分不出来。分组密码的解密要用到 $F_k^{-1}$，所以实际要求的是“强”版本。
:::

::: qa 分组密码本身能直接当加密方案用吗？
不能。$F_k$ 是**确定性**的，同一个分组每次加密都得到同一个结果，按上一讲的结论，任何确定性方案都不可能 CPA 安全；而且它只能加密**固定长度** $\ell$ 的一块。要加密长消息，还需要下一节的“工作模式”。
:::

::: tldr
分组密码 = 高效可逆的带密钥置换 $F_k:\{0,1\}^\ell\to\{0,1\}^\ell$；理论上要求它是（强）伪随机置换，实践中要求没有比穷举 $2^n$ 更好的攻击。
:::

<div class="part-label">PART 2 · 用分组密码加密 MODES OF OPERATION</div>

## 6.2 工作模式

::: def 工作模式 Modes of Operation @P10
分组密码（或流密码）**不会单独**作为加密方案使用。**工作模式**提供了一种用流密码或分组密码**安全且高效地加密长消息**的方法：

$$\text{分组/流密码} + \text{工作模式} = \text{长消息加密方案}$$

<span class="muted">（课件原文写作 “block/string ciphers”，应为 block/stream ciphers。）</span>
:::

早期几种著名的分组密码工作模式 <Src p="12" />：

- 电码本模式 <span class="en">Electronic Code Book, ECB</span>
- 密文分组链接模式 <span class="en">Cipher Block Chaining, CBC</span>
- 输出反馈模式 <span class="en">Output Feedback, OFB</span>
- 计数器模式 <span class="en">Counter, CTR</span>

下面统一记号：$F$ 是分组长度为 $n$ 的分组密码，待加密消息为 $m = m_1, m_2, \dots, m_\ell$，每个 $m_i \in \{0,1\}^n$ 是一个明文分组 <Src p="13" />。

<span class="muted">注：这里课件沿用教材第 3 章的记号，用 $n$ 表示**分组长度**、$\ell$ 表示**分组个数**，与 6.1 节定义中“$n$ 是密钥长度、$\ell$ 是分组长度”的用法不同，阅读时注意区分。</span>

### 6.2.1 ECB 模式

::: def 电码本模式 ECB @P13
ECB 是一种朴素的模式，每个分组各自独立加密：

$$c := \langle F_k(m_1),\ F_k(m_2),\ \dots,\ F_k(m_\ell) \rangle$$

解密时逐块计算 $m_i = F_k^{-1}(c_i)$。
:::

<Fig src="/img/06/p013.jpg" size="md" cap="图 1：电码本（ECB）模式" p="13" />

::: warn ECB 的安全性 @P14
- 它是**确定性**的，因此**不可能是 CPA 安全**的；
- 不安全，<span class="hl">永远不要使用</span>。
:::

<Fig src="/img/06/p014.jpg" cap="图 2：ECB 的危险。中间是左图用 ECB 加密的结果，右图是用安全模式加密的结果（来自 Wikipedia，原图由 Larry Ewing 用 GIMP 制作）" p="14" />

<L06EcbPenguin />

::: qa ECB 连“只窃听”的敌手（EAV）都挡不住，为什么？
<span class="muted">（补充说明）</span>敌手选 $m_0 = 0^n \| 0^n$（两块相同）、$m_1 = 0^n \| 1^n$（两块不同）。收到挑战密文 $c_1 \| c_2$ 后：若 $c_1 = c_2$ 就输出 0，否则输出 1。由于 $F_k$ 是置换，$m_1$ 的两块不同，所以它的两块密文也一定不同；$m_0$ 的两块密文一定相同，因此敌手**以概率 1 获胜**。连窃听安全都做不到，CPA 安全就更不用说了。
:::

### 6.2.2 CBC 模式

::: def 密文分组链接模式 CBC @P15
- 每次加密一条消息，都**均匀随机**地选择一个初始向量 IV；
- 明文分组在送进 $F_k$ 之前先被“随机化”，即与前一块密文异或：

$$c_0 := IV,\qquad c_i := F_k(c_{i-1} \oplus m_i),\quad i = 1, \dots, \ell.$$

- 密文为 $\langle c_0, c_1, \dots, c_\ell \rangle$（IV 以明文形式随密文一起发送）；
- 解密需要 $F_k^{-1}$，即 $F_k$ **必须可逆**：

$$m_i := F_k^{-1}(c_i) \oplus c_{i-1}.$$
:::

<Fig src="/img/06/p015.jpg" size="md" cap="图 3：密文分组链接（CBC）模式" p="15" />

::: def CBC 的安全性与缺点 @P16
- CBC 模式的加密是**概率性**的；
- 若 $F$ 是 PRF，则 CBC 模式加密是 **CPA 安全**的；
- **主要缺点**：加密是**串行**的，无法并行化。

<span class="muted">注：CBC 解密要用 $F_k^{-1}$，所以 $F$ 必须是置换。教材的表述是“若 $F$ 是伪随机**置换**（PRP），则 CBC 模式 CPA 安全”，课件写成 PRF 不够严谨。</span>
:::

::: ex [补充说明] CBC 的两个细节
1. **解密可以并行**：$m_i = F_k^{-1}(c_i)\oplus c_{i-1}$ 只依赖两块已知的密文，所有块可以同时解密。串行的只是加密。
2. **IV 必须不可预测**：若敌手能事先猜到下一条消息的 IV（例如 SSL 3.0 / TLS 1.0 用上一条消息的最后一块密文当作下一条的 IV，即所谓“链式 CBC”），就能构造出 CPA 攻击（2011 年的 BEAST 攻击即利用了这一点）。
:::

::: exam [考点] 2025 期中 Q6：CBC 的“变种”为什么不安全
期中第 6 题给出一种 CBC 变体：最后一个**不完整**的明文分组 $m_\ell$ 不再与 $c_{\ell-1}$ 异或，而是用 $c_{\ell-1}$ 的若干比特把 $m_\ell$ 补齐后直接送进 $F_k$，补进去的那些比特随后从 $c_{\ell-1}$ 中丢掉，要求证明它不是 CPA 安全的。

**要点**：CBC 安全的根源是**每一块进入 $F_k$ 之前都被前一块密文随机化**。这个变体中最后一块的前半部分完全由敌手控制，只剩少量随机填充位，$F_k$ 的输入取值很少。敌手可以通过多次加密查询，把“固定前缀 $m_{0\ell}$ + 所有可能的填充”对应的 $c_\ell$ 都收集起来，再看挑战密文的 $c_\ell$ 是否落在这个集合里。以填充 1 位为例，查询 $q(n)$ 次后，获胜概率为 $1 - \frac{1}{2^{q(n)+1}}$。

**一般规律**：凡是某一块进入 $F_k$ 时**没有经过新鲜随机数的掩盖**，这一块的加密就退化为确定性的 ECB，CPA 安全随之失效。
:::

### 6.2.3 OFB 模式

::: def 输出反馈模式 OFB @P17
- 每条要加密的明文都生成一个**均匀随机**的 IV；
- 为每个分组生成“随机”的填充（pad）：$y_0 := IV$，$y_i := F_k(y_{i-1})$；
- 把填充与明文分组异或：$c_i := m_i \oplus y_i$；
- 密文为 $\langle IV, c_1, c_2, \dots, c_\ell \rangle$。
:::

<Fig src="/img/06/p017.jpg" size="md" cap="图 4 / 图 5：输出反馈（OFB）模式（P17、P18 为同一张图）" p="17–18" />

::: def OFB 的优缺点 @P18
- $F_k$ **不要求可逆**；
- 若 $F$ 是 PRF，则 OFB 模式加密是 **CPA 安全**的；
- **支持预计算**：虽然加密和解密都是串行的，但加解密用的填充可以在**明文还没到**时就提前算好。
:::

::: qa 为什么 OFB 不要求 $F_k$ 可逆？
因为解密时接收方用同一个 IV **正向**地重新算出 $y_1, y_2, \dots$，再计算 $m_i = c_i \oplus y_i$，整个过程只用到 $F_k$，从不调用 $F_k^{-1}$。OFB 实际上是把分组密码当成**伪随机生成器**，造出一条密钥流，本质上是一个流密码。
:::

### 6.2.4 CTR 模式

::: def 计数器模式 CTR @P19
- 每条要加密的明文都生成一个**均匀随机**的值 $ctr$；
- 为每个分组生成“随机”填充：$y_i := F_k(ctr + i)$，再与明文分组异或：$c_i := m_i \oplus y_i$；
- 密文为 $\langle ctr, c_1, c_2, \dots, c_\ell \rangle$。

<span class="muted">（$ctr + i$ 按模 $2^n$ 计算。）</span>
:::

<Fig src="/img/06/p019.jpg" size="md" cap="图 6 / 图 7：计数器（CTR）模式（P19、P20 为同一张图）" p="19–20" />

::: def CTR 的优缺点 @P20
- 与 OFB 模式非常相似；
- 若 $F$ 是 PRF，则 CTR 模式加密是 **CPA 安全**的（即教材定理 3.32，见课后阅读 <Src p="46" />）；
- **加密和解密都可以并行**。
:::

::: ex [补充说明] 定理 3.32 的证明：若 $F$ 是 PRF，则随机计数器模式是 CPA 安全的
设 $\Pi$ 为 CTR 模式方案，$\tilde\Pi$ 为把 $F_k$ 换成**真随机函数** $f$ 后的同一方案。设敌手 $\mathcal{A}$ 运行时间为多项式，它至多发起 $q = q(n)$ 次加密查询，每次查询（以及挑战消息）至多 $q$ 个分组。

**第 1 步：从 $\Pi$ 换到 $\tilde\Pi$。** 构造区分器 $D$：$D$ 拿着预言机 $\mathcal{O}$（要么是 $F_k$，要么是 $f$）模拟 CPA 实验，用 $\mathcal{O}$ 计算所有填充，最后在 $\mathcal{A}$ 猜对时输出 1。当 $\mathcal{O}=F_k$ 时，$\mathcal{A}$ 看到的恰好是 $\Pi$ 的实验；当 $\mathcal{O}=f$ 时，恰好是 $\tilde\Pi$ 的实验。由 $F$ 是 PRF（$D$ 是多项式时间的），

$$\Big|\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A},\Pi}(n)=1]-\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A},\tilde\Pi}(n)=1]\Big| = \Big|\Pr[D^{F_k}=1]-\Pr[D^{f}=1]\Big| \le \mathsf{negl}(n).$$

**第 2 步：分析 $\tilde\Pi$。** 设挑战密文使用的计数器为 $ctr^*$，用到 $f(ctr^*+1),\dots,f(ctr^*+\ell^*)$；第 $i$ 次查询的计数器为 $ctr_i$，用到 $f(ctr_i+1),\dots,f(ctr_i+\ell_i)$。定义事件 $\mathsf{Overlap}$：存在某个 $i$，使这两段计数器区间有交集。

- 若 $\mathsf{Overlap}$ **不发生**：挑战用到的 $f$ 值从未在别处出现过，又因为 $f$ 是真随机函数，所以它们是均匀且与 $\mathcal{A}$ 的全部视图独立的，于是挑战密文 $c_j = m_{b,j}\oplus f(ctr^*+j)$ 就是**一次一密**，$\mathcal{A}$ 只能瞎猜：$\Pr[\text{成功}\mid\overline{\mathsf{Overlap}}]=\tfrac12$。
- **估计 $\Pr[\mathsf{Overlap}]$**：固定第 $i$ 次查询，两段长度分别为 $\ell^*,\ell_i\le q$ 的区间相交，当且仅当 $ctr_i-\ell^*+1 \le ctr^* \le ctr_i+\ell_i-1$，这样的 $ctr^*$ 至多 $\ell^*+\ell_i-1 \le 2q-1$ 个。$ctr^*$ 是均匀选取的，所以 $\Pr[\mathsf{Overlap}_i]\le \frac{2q-1}{2^n}$。对 $q$ 次查询取联合界：$\Pr[\mathsf{Overlap}]\le \frac{2q^2}{2^n}$。

因此（全概率公式，并用 $\Pr[\text{成功}\wedge\mathsf{Overlap}]\le\Pr[\mathsf{Overlap}]$）：

$$\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A},\tilde\Pi}(n)=1] \le \tfrac12 + \Pr[\mathsf{Overlap}] \le \tfrac12 + \frac{2q^2}{2^n}.$$

**第 3 步：合并。** $\Pr[\mathsf{PrivK}^{\mathsf{cpa}}_{\mathcal{A},\Pi}(n)=1] \le \tfrac12 + \frac{2q^2}{2^n} + \mathsf{negl}(n)$。$q$ 是多项式，$\frac{2q^2}{2^n}$ 可忽略，两个可忽略函数之和仍可忽略，证毕。$\blacksquare$
:::

### 6.2.5 四种模式对比

<L06ModeLab />

| | ECB | CBC | OFB | CTR |
|---|---|---|---|---|
| 加密公式 | $c_i=F_k(m_i)$ | $c_i=F_k(c_{i-1}\oplus m_i)$ | $c_i=m_i\oplus y_i,\ y_i=F_k(y_{i-1})$ | $c_i=m_i\oplus F_k(ctr+i)$ |
| 随机化 | ✗ 确定性 | 随机 IV | 随机 IV | 随机 ctr |
| CPA 安全 | ✗ | ✓（$F$ 为 PRP） | ✓（$F$ 为 PRF） | ✓（$F$ 为 PRF） |
| 需要 $F_k^{-1}$ | 需要 | 需要 | 不需要 | 不需要 |
| 加密并行 | ✓ | ✗ | ✗（填充可预计算） | ✓ |
| 解密并行 | ✓ | ✓ <span class="muted">（补充）</span> | ✗（填充可预计算） | ✓ |
| 1 位密文差错的影响 <span class="muted">（补充）</span> | 本块乱码 | 本块乱码 + 下一块同位置翻转 | 仅同一位 | 仅同一位 |

::: warn [补充说明] IV / ctr 绝不能重复使用
OFB 和 CTR 本质是流密码：若两条消息用了同一个 IV（或 ctr），它们的填充完全相同，$c\oplus c' = m\oplus m'$，就退化成“两次一密”。在上面的实验台里勾选“两次加密用同一个 IV”，就能看到两次密文完全一样。
:::

::: tldr
ECB 是确定性的，永远别用；CBC、OFB、CTR 靠随机 IV / ctr 实现 CPA 安全。CBC 加密串行且需要 $F^{-1}$；OFB、CTR 只需正向 $F$，其中 CTR 还能完全并行。
:::

## 6.3 “好”分组密码的雪崩效应

::: prin 雪崩效应 Avalanche Effect @P23
我们想设计一个**接近随机置换**的分组密码，因此特别要让它具备随机置换所具有的一个重要性质：

**输入的微小改变必须“影响”输出的每一个比特。**

这一性质称为**雪崩效应**。
:::

::: ex [补充说明] 怎样量化“影响每一位”
对随机置换而言，把输入翻转 1 位，输出的每一位都**以约 1/2 的概率**独立地翻转，平均翻转 $\ell/2$ 位。实际设计中常用这一标准来检验（严格雪崩准则 <span class="en">Strict Avalanche Criterion</span>）。下一节的 Toy16 演示里可以看到，差异位数一轮轮增长，最终稳定在 16 位中的约 8 位。
:::

::: tldr
雪崩效应：改 1 位输入，输出约一半的位都要变，而且无法预测是哪些位。
:::

## 6.4 代换-置换网络（SPN）

### 6.4.1 混淆-扩散范式

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 170px;gap:18px;align-items:center">
<div>

::: def 混淆-扩散范式 Confusion-Diffusion Paradigm @P25
为了构造分组密码（伪随机置换），SPN 遵循**混淆-扩散范式**：

- 由 Claude E. Shannon 提出；
- 用许多**分组长度小**的随机（或看似随机）置换 $\{f_i\}$，构造出一个**分组长度大**、看起来随机的置换 $F$。
:::

</div>
<Fig src="/img/06/p025.jpg" cap="图 8：Claude Elwood Shannon（1916–2001），照片来自其 Wikimedia 页面" p="25" />
</div>

具体做法 <Src p="26" />：

- 整个构造通常重复多轮“**混淆步** + **扩散步**”；
- 分组密码的输入被切成若干个**小块**；
- 每一轮中：
  - **混淆**：每个小块送进一个小的随机置换（通常称为**轮函数** <span class="en">round function</span>），给输出引入混淆；
  - **扩散**：再用一个**混合置换** <span class="en">mixing permutation</span> 把所有块的比特打乱混合。

::: qa 为什么不直接用一个大的随机置换？
<span class="muted">（补充说明）</span>描述 $\{0,1\}^{64}$ 上的一个随机置换需要约 $\log_2(2^{64}!) \approx 64\cdot 2^{64}$ 比特，根本存不下。小置换（如 8 位输入）只要一张 256 项的表。混淆-扩散范式的思路是：用若干个小表加上比特打乱，**拼出**一个“看起来像”大随机置换的东西。
:::

### 6.4.2 SPN 的结构

::: def 代换-置换网络 Substitution-Permutation Network @P27
SPN 是一种基于混淆-扩散范式（的一个变体）的实用分组密码构造。每一轮依次执行：

1. **密钥混合** <span class="en">Key mixing</span>：输入先与本轮的**子密钥**（轮密钥）异或；
2. **代换** <span class="en">Substitution</span>：密钥混合之后，第 $i$ 块送进一个固定的、**可逆的**“代换函数”（即置换）$S_i$，称为 **S 盒**；
3. **置换** <span class="en">Permutation</span>：把所有 S 盒输出的比特重新排列（置换）。

代换步和置换步的细节都是**公开**的，任何攻击者都知道，只有密钥保密（这正是 **Kerckhoffs 原则**）。
:::

<Fig src="/img/06/p028.jpg" size="md" cap="图 9：64 位 SPN 的单轮：⊕ 64 位子密钥 → 切成 8 个 8 位块分别过 S 盒 → 混合置换" p="28" />

::: def 多轮 SPN @P29
- 每一轮的输出作为下一轮的输入；
- 最后一轮之后，还有一次**最终的密钥混合**，其结果就是密码的输出；
- 每一轮使用**不同的子密钥**。子密钥由分组密码的**主密钥**按照**密钥编排** <span class="en">key schedule</span> 生成；
- 总结：一个 $r$ 轮 SPN 有 $r$ 个完整的轮（密钥混合 + S 盒代换 + 混合置换），最后再加一次密钥混合。<span class="hl">这样的 SPN 共使用 $r+1$ 个子密钥。</span>
:::

<Fig src="/img/06/p030.jpg" size="md" cap="图 10：一个 64 位的 SPN（多轮叠加）" p="30" />

::: qa 为什么最后还要再做一次密钥混合？
<span class="muted">（补充说明，见教材 6.2.1 节）</span>如果最后一轮以 S 盒和置换结束，由于它们公开且可逆，攻击者拿到输出后可以直接把这两步**倒推回去**。这两步对安全毫无贡献，相当于少了一轮。最后加一次密钥混合，就把公开的步骤“锁”在了密钥后面。
:::

::: def [命题] S 盒可逆 ⇒ SPN 是置换 @P27
<span class="muted">（补充说明：课件 P27 要求 S 盒可逆，下面说明原因。）</span>

**命题**：若所有 S 盒都可逆，则对任意主密钥，SPN 都是一个置换，并且给定密钥可以高效求逆。

**证明**：SPN 是若干步骤的复合，只需说明每一步都可逆：

1. **密钥混合** $x \mapsto x \oplus k_i$：异或同一个值两次等于恒等，所以逆运算就是它自己，$(x\oplus k_i)\oplus k_i = x$；
2. **代换**：把状态切成小块，第 $j$ 块经过 $S_j$。由于每个 $S_j$ 都是双射，逐块用 $S_j^{-1}$ 即可还原。各块互不干扰，所以整体也是双射；
3. **混合置换**：只是重排比特的位置，按相反的方式重排即可还原。

可逆函数的复合仍可逆，其逆为各步的逆**倒序**复合：解密时先 $\oplus k_{r+1}$，再依次执行“逆置换 → 逆 S 盒 → $\oplus k_i$”，$i = r, \dots, 1$。$\blacksquare$
:::

### 6.4.3 SPN 中的雪崩效应

::: prin SPN 怎样产生雪崩效应 @P31
雪崩效应主要靠下面两条设计引入 SPN：

1. **S 盒**的设计：改变 S 盒输入的**任意 1 位**，输出**至少改变 2 位**；
2. **混合置换**的设计：任何一个 S 盒的输出位，都会作为下一轮**多个不同 S 盒**的输入。
:::

::: ex [补充说明] 粗略估算需要几轮
在最好的情况下，输入 1 位差异 → 第 1 轮 S 盒后至少 2 位 → 置换把这 2 位送进 2 个不同 S 盒 → 第 2 轮后至少 4 位 → 第 3 轮后至少 8 位……即 $r$ 轮后约 $2^r$ 位。分组长 $\ell$ 位时，至少需要约 $\log_2 \ell$ 轮差异才可能波及所有位（64 位分组约 6 轮）。实际密码会在此基础上再加好几轮作为安全余量。
:::

<L06SpnAvalanche />

::: warn [补充说明] S 盒必须是非线性的
如果 S 盒是线性（或仿射）的，整个 SPN 就是输入与密钥的一个**线性函数**，攻击者只需几个明密文对，解一个线性方程组就能求出密钥。在上面的演示里勾选“去掉 S 盒”：1 位差异永远只是 1 位，完全没有雪崩。S 盒是 SPN 中**唯一的非线性来源**。
:::

::: tldr
SPN = $r$ 轮“⊕ 子密钥 → S 盒 → 比特置换”+ 最后一次 ⊕ 子密钥（共 $r+1$ 个子密钥）。S 盒可逆保证整体可逆；“S 盒改 1 位至少变 2 位”加上“置换把输出分散到多个 S 盒”，共同产生雪崩效应。
:::

## 6.5 Feistel 网络

::: def Feistel 网络 @P33
Feistel 网络是构造分组密码的**另一种**方法：

- 以德裔物理学家、密码学家 **Horst Feistel**（1915–1990）命名，他在 IBM 工作期间做了开创性研究；
- Feistel 网络提供了一种**用不可逆的部件构造可逆函数**的方法（这一点与 SPN 不同：其底层函数**不必可逆**）；
- Feistel 网络由若干轮组成，每轮使用一个**带密钥的轮函数**。
:::

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 240px;gap:18px;align-items:center">
<div>

::: def 平衡 Feistel 网络的细节 @P34
在一个 $\ell$ 位的**平衡** Feistel 网络中，第 $i$ 轮的轮函数 $\hat f_i$ 以子密钥 $k_i$ 和一个 $\ell/2$ 位串为输入，输出 $\ell/2$ 位串。定义 $f_i:\{0,1\}^{\ell/2}\to\{0,1\}^{\ell/2}$ 为

$$f_i(R) \overset{\text{def}}{=} \hat f_i(k_i, R).$$

第 $i$ 轮的输出 $(L_i, R_i)$ 为：

$$L_i := R_{i-1},\qquad R_i := L_{i-1} \oplus f_i(R_{i-1}).$$

求逆：

$$R_{i-1} := L_i,\qquad L_{i-1} := R_i \oplus f_i(R_{i-1}).$$

注意：轮函数 $\hat f_i$ 是**固定且公开**的，但 $f_i$ **不是**（它依赖于秘密的子密钥 $k_i$）。
:::

</div>
<Fig src="/img/06/p034.jpg" cap="图 11：三轮 Feistel 网络" p="34" />
</div>

::: def [命题] 无论 $f_i$ 是否可逆，Feistel 网络都是置换 @P34
<span class="muted">（补充说明：把课件的求逆公式写成完整证明。）</span>

**证明**：只需证明单轮映射 $\Phi_i:(L_{i-1},R_{i-1})\mapsto(L_i,R_i)$ 是双射，多轮复合自然也是双射。

给定一轮的输出 $(L_i, R_i)$，下面说明输入被**唯一确定**：

1. 由 $L_i = R_{i-1}$（轮的定义）直接得到 $R_{i-1} = L_i$；
2. 有了 $R_{i-1}$ 就能**正向**计算 $f_i(R_{i-1})$（$f_i$ 由公开的 $\hat f_i$ 和已知的 $k_i$ 决定，只需正向计算，不需要求逆）；
3. 由 $R_i = L_{i-1}\oplus f_i(R_{i-1})$，两边同时异或 $f_i(R_{i-1})$，利用 $a\oplus a = 0$，得 $L_{i-1} = R_i \oplus f_i(R_{i-1})$。

因此 $\Phi_i^{-1}(L_i,R_i) = \big(R_i\oplus f_i(L_i),\ L_i\big)$ 有定义，且 $\Phi_i^{-1}\circ\Phi_i$ 是恒等映射，即 $\Phi_i$ 是双射。整个过程**只正向调用** $f_i$，所以 $f_i$ 是否可逆无关紧要。$\blacksquare$
:::

::: ex [补充说明] 解密 = 同一电路 + 轮密钥倒序
设 $\mathsf{swap}(L,R)=(R,L)$。由上面的求逆公式可以得到

$$\Phi_i^{-1} = \mathsf{swap}\circ\Phi_i\circ\mathsf{swap},$$

验证如下（第二步按轮的定义：左边换成原来的右半，右半变成“左半 ⊕ $f_i$(右半)”）：

$$
\begin{aligned}
\mathsf{swap}\circ\Phi_i\circ\mathsf{swap}\,(L_i,R_i)
&= \mathsf{swap}\circ\Phi_i\,(R_i,L_i)\\
&= \mathsf{swap}\,\big(L_i,\ R_i\oplus f_i(L_i)\big)\\
&= \big(R_i\oplus f_i(L_i),\ L_i\big) = \Phi_i^{-1}(L_i,R_i).
\end{aligned}
$$

于是

$$\Phi_1^{-1}\circ\cdots\circ\Phi_r^{-1} = \mathsf{swap}\circ\Phi_1\circ\cdots\circ\Phi_r\circ\mathsf{swap},$$

（相邻两个 $\mathsf{swap}$ 复合为恒等，中间的全部抵消。）

即：**把密文左右交换，按 $k_r, k_{r-1}, \dots, k_1$ 的顺序跑同一个 Feistel 网络，再交换一次**，就得到明文。DES 的硬件实现正是利用这一点，用一套电路同时完成加密和解密。
:::

<L06Feistel />

::: ex [补充说明] Luby–Rackoff 定理
若各轮函数 $f_i$ 是独立的伪随机函数（PRF），那么 **3 轮** Feistel 网络是伪随机置换（PRP），**4 轮**是**强**伪随机置换（教材第 7 章）。这正好呼应了 6.1 节“分组密码应当是（强）PRP”的要求：Feistel 结构可以把 PRF 变成 PRP。
:::

| | SPN | Feistel 网络 |
|---|---|---|
| 每轮处理 | 整个分组 | 只改半个分组（另一半原样换到左边） |
| 部件要求 | S 盒**必须可逆** | 轮函数**可以不可逆** |
| 解密 | 需要逆 S 盒、逆置换 | 同一结构，轮密钥倒序 |
| 代表 | AES | DES |

::: tldr
Feistel：$L_i = R_{i-1}$，$R_i = L_{i-1}\oplus f_i(R_{i-1})$。求逆只需正向调用 $f_i$，所以即使 $f_i$ 不可逆，整体也一定可逆；解密就是把轮密钥倒过来用。
:::

## 6.6 DES

::: def DES 数据加密标准 @P37
DES 是一个基于 **Feistel 网络**、被广泛使用的分组密码：

- **16 轮**，分组长度 **64 位**，密钥长度 **56 位**；
- 轮函数（有时称为 **mangler 函数**）以 **48 位子密钥**和 **32 位输入**为输入，输出 **32 位**；
- 设计精良：已知最好的**实用**攻击仍然是对密钥空间的**穷举搜索**；
- 缺点：<span class="hl">密钥太短</span>；
- 已被 AES 取代。
:::

<Fig src="/img/06/p038.jpg" size="md" cap="图 12：DES 的 mangler（轮）函数" p="38" />

::: ex [读图] DES 轮函数的四步 @P38
1. **扩展 E**：32 位输入扩展成 48 位（部分比特被复制）；
2. **与 48 位子密钥异或**（密钥混合）；
3. **8 个 S 盒**：48 位切成 8 个 6 位块，每个 S 盒把 **6 位压成 4 位**，共输出 32 位；
4. **置换**：把 32 位重新排列，得到输出。

<span class="muted">（补充说明）</span>可以看到，mangler 函数本身就是一个“小 SPN 轮”。但它的 S 盒是 6 进 4 出，**不可能可逆**，这正好由外层的 Feistel 结构兜底。扩展 E 让每个输入位影响两个 S 盒，加快了雪崩。
:::

::: ex [补充说明] 56 位到底有多短
$2^{56}\approx 7.2\times10^{16}$。1998 年，EFF 花约 25 万美元造的专用机 “Deep Crack” 用 56 小时破解了 DES 挑战；1999 年它与 distributed.net 联手，把时间缩短到 22 小时 15 分钟。如今用租来的 GPU / FPGA，一天之内即可穷举。
:::

::: tldr
DES = 16 轮 Feistel，64 位分组，56 位密钥；结构没问题，败在密钥太短。
:::

## 6.7 三重 DES（3DES）

::: def 3DES 概况 @P40
为了解决 DES 密钥长度不足的问题，人们设计了三重 DES：

- **1999 年**标准化；
- 达到 **112 位**安全强度；
- 由于如今推荐的最小密钥长度是 **128 位**，建议用支持 128 / 192 / 256 位密钥的**高级加密标准 AES** 替换 3DES；
- 美国国家标准与技术研究院（NIST）已在 **2023 年底前**弃用 DES 和 3DES 的所有应用。

<span class="muted">（细抠：NIST SP 800-131A Rev.2 规定 2023 年后不再允许用 3DES <b>加密</b>，但仍允许为兼容旧数据而<b>解密</b>；另外“112 位安全强度”指三密钥版本，NIST SP 800-57 只给两密钥版本约 80 位的强度。补充说明）</span>
:::

::: def 3DES 的两个变体 @P41
**变体 1（三密钥）**：选三个独立的密钥 $k_1, k_2, k_3$，定义

$$F''_{k_1,k_2,k_3}(x) \overset{\text{def}}{=} F_{k_3}\big(F^{-1}_{k_2}(F_{k_1}(x))\big).$$

**变体 2（两密钥）**：选两个独立的密钥 $k_1, k_2$，定义

$$F''_{k_1,k_2}(x) \overset{\text{def}}{=} F_{k_1}\big(F^{-1}_{k_2}(F_{k_1}(x))\big).$$
:::

::: qa 中间那一步为什么用解密 $F^{-1}_{k_2}$，而不是再加密一次？
<span class="muted">（补充说明）</span>为了**向后兼容**。令 $k_1 = k_2 = k_3 = k$，则 $F_k(F_k^{-1}(F_k(x))) = F_k(x)$，三重 DES 退化为单 DES，新设备可以和只支持单 DES 的老设备互通。安全性上，“加密—解密—加密”（EDE）与“加密三次”没有区别，因为 $F^{-1}_{k_2}$ 同样是一个依赖密钥的置换。
:::

::: qa 为什么不用更省事的“双重 DES” $F_{k_2}(F_{k_1}(x))$？
因为**中间相遇攻击** <span class="en">meet-in-the-middle</span>（课后阅读：教材 6.2.4 节 <Src p="46" />）。给定明密文对 $(x, y)$，满足 $y = F_{k_2}(F_{k_1}(x))$ 当且仅当 $F_{k_1}(x) = F^{-1}_{k_2}(y)$，即两边在“中间”相遇：

1. 对所有 $2^n$ 个 $k_1$ 计算 $z_1 = F_{k_1}(x)$，连同 $k_1$ 存入表中（按 $z_1$ 排序或哈希）；
2. 对所有 $2^n$ 个 $k_2$ 计算 $z_2 = F^{-1}_{k_2}(y)$，在表中查找 $z_2$；每个命中的 $(k_1,k_2)$ 都是候选；
3. 候选约有 $2^{2n}/2^{\ell}$ 个（$\ell$ 为分组长），再用另外一两对明密文过滤即可。

总代价约 $2\cdot 2^n$ 次分组密码运算、$2^n$ 的存储，而不是 $2^{2n}$。对 DES 来说，双重加密只有约 $2^{57}$ 的强度，几乎没有提升。同样的方法用在三重加密上，只能“剥掉”一层，代价约 $2^{2n}$，这就是 168 位密钥的 3DES 只有 **112 位**安全强度的原因。
:::

<L06TripleDes />

::: tldr
3DES = EDE 结构 $F_{k_3}(F^{-1}_{k_2}(F_{k_1}(x)))$。中间用解密是为了兼容单 DES；因为中间相遇攻击，三密钥版本的强度只有 112 位。已被 NIST 弃用。
:::

## 6.8 AES

::: def AES 高级加密标准 @P43
AES 是 NIST 于 **2001 年**确立、被广泛使用的加密标准：

- 分组长度 **128 位**；
- 支持 **128 位（10 轮）**、**192 位（12 轮）**、**256 位（14 轮）**密钥；
- 采用**代换-置换网络（SPN）**结构；
- 没有比穷举密钥更好的**实用**密码分析攻击；
- 美国国家安全局（NSA）允许用 AES-256 加密密级高达“**绝密**”（TOP SECRET）的数据。

脚注：美国有三个密级：机密（Confidential）、秘密（Secret）、绝密（Top Secret）。来自 Wikipedia 词条 “Classified information in the United States”。
:::

<Fig src="/img/06/p044.webp" size="md" cap="图 13：AES 轮函数。每一轮中，S 盒对每个字节块 A<sub>i</sub> 做“代换”，结果 B<sub>i</sub> 经过行移位与列混合完成“置换”，得到的 C<sub>i</sub> 再与轮密钥的字节 k<sub>i</sub> 异或（图源 Wikimedia）" p="44" />

AES 的 128 位状态被排成一个 **4×4 字节矩阵**，每一轮依次执行四步 <Src p="44" />：

| 步骤 | 作用 | 对应 SPN 中的 |
|---|---|---|
| **SubBytes** 字节代换 | 每个字节查同一张 8 位 S 盒 | 代换（混淆） |
| **ShiftRows** 行移位 | 第 $r$ 行循环左移 $r$ 字节 | 置换（扩散） |
| **MixColumns** 列混合 | 每列左乘一个固定的 4×4 矩阵（在 GF(2⁸) 上） | 置换（扩散） |
| **AddRoundKey** 轮密钥加 | 与 128 位轮密钥异或 | 密钥混合 |

<span class="muted">（补充说明）</span>细节：第一轮之前先做一次 AddRoundKey，最后一轮**省略 MixColumns**，所以 AES-128 共用 $10+1 = 11$ 个轮密钥，与 6.4 节“$r$ 轮 SPN 用 $r+1$ 个子密钥”一致。另外，MixColumns 并不是单纯的“比特换位”，而是一个可逆的线性变换，所以严格说 AES 是 SPN 的**推广形式**。

<L06AesRound />

::: ex [补充说明] AES 的来历与现状
AES 原名 **Rijndael**，由比利时密码学家 Joan Daemen 与 Vincent Rijmen 设计，1997–2000 年在 NIST 公开征集中胜出。目前已知最好的密钥恢复攻击（2011 年的 biclique 攻击）对 AES-128 约需 $2^{126.1}$ 次运算，仅比穷举快约 4 倍，没有实际意义，这与课件“没有比穷举更好的**实用**攻击”的说法一致。
:::

::: tldr
AES = 128 位分组的 SPN，10 / 12 / 14 轮；每轮依次是 SubBytes → ShiftRows → MixColumns → AddRoundKey，最后一轮没有 MixColumns。两轮之内即可让 1 字节的差异扩散到全部 16 字节。
:::

## ★ 本讲速记

:::: recap
::: card 分组密码
- 高效、带密钥的置换 $F_k:\{0,1\}^\ell\to\{0,1\}^\ell$
- $n$ 密钥长度，$\ell$ 分组长度
- 理论：（强）PRP；实践：最好攻击 ≈ $2^n$
:::
::: card 工作模式
- ECB：确定性，不 CPA 安全，别用
- CBC：$c_i=F_k(c_{i-1}\oplus m_i)$，加密串行，需 $F^{-1}$
- OFB：$y_i=F_k(y_{i-1})$，可预计算
- CTR：$y_i=F_k(ctr+i)$，可并行
- IV / ctr 必须随机且不重复
:::
::: card 雪崩与 SPN
- 改 1 位输入，约一半输出位翻转
- 每轮：⊕ 子密钥 → S 盒 → 置换
- $r$ 轮 + 末尾密钥混合，共 $r+1$ 个子密钥
- S 盒可逆 ⇒ SPN 可逆；S 盒是唯一非线性来源
:::
::: card Feistel
- $L_i=R_{i-1}$，$R_i=L_{i-1}\oplus f_i(R_{i-1})$
- $f_i$ 不必可逆，整体仍可逆
- 解密 = 同一结构 + 轮密钥倒序
:::
::: card DES / 3DES
- DES：16 轮 Feistel，64 位分组，56 位密钥（太短）
- 3DES：$F_{k_3}(F^{-1}_{k_2}(F_{k_1}(x)))$，EDE 兼容单 DES
- 中间相遇 ⇒ 双重加密约 $2^{n+1}$，3DES 约 112 位
- NIST 已于 2023 年底弃用
:::
::: card AES
- 2001 年，128 位分组，SPN
- 128 / 192 / 256 位密钥 ↔ 10 / 12 / 14 轮
- SubBytes → ShiftRows → MixColumns → AddRoundKey
- 最后一轮无 MixColumns
:::
::::
