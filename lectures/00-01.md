## 0.3 密码学能做什么？

### 0.3.1 两大用途：保密性与完整性

我们常用密码学在公共网络上实现**安全通信**，即达成：

::: def 保密性 Secrecy / Confidentiality @P28
除预期接收者 Bob 外，任何人（例如敌手 Adversary）都不能获知消息 $M$ 的内容。
:::

::: def 完整性 Integrity / Authenticity @P29
- Bob 收到的消息 $M'$ **未被篡改**，即 $M' = M$；
- 发送者信息正确（例如 $M'$ 确实是 Alice 发的）。
  <span class="muted">注：当发送者信息本身就包含在消息里时，第二条要求被第一条覆盖。</span>
:::

<Fig src="/img/00-01/p027.jpg" size="md" cap="经公共网络的（安全）通信：Alice 发出 M，Bob 收到 M′，中间的敌手可窃听或篡改" p="27–29" />

<CommDemo />

#### 为什么完整性很重要？ <Src p="30" />

一个针对数据完整性的简单攻击：Alice 给银行发“请从我的账户转 ¥5000 给 Bob”，Eve 在途中把它改成“请从我的账户转 ¥500000 给 Eve”。**即使消息被加密，如果没有完整性保护，篡改仍可能发生**——保密性 ≠ 完整性。

## 1.1 凯撒密码与移位密码

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 170px;gap:18px;align-items:center">
<div>

**凯撒密码**（Caesar's cipher）<Src p="57" />：

- 最简单、最广为人知的加密技术之一；
- 以尤利乌斯·凯撒命名，他曾用它书写机密信件；
- 它是一种**移位密码**；
- <span class="hl">不安全，很容易被破解。</span>

</div>
<Fig src="/img/00-01/p057.jpg" cap="凯撒（前 100–前 44）" p="57" />
</div>

::: def 凯撒密码 @P58–60
**加密**：字母表中每个字母向后移 3 位；**解密**：向前移 3 位。

`Enc: a→D, b→E, …, w→Z, x→A, y→B, z→C`
`Dec: D→a, E→b, …, Z→w, A→x, B→y, C→z`

例：密文 `VHHXWRPRUURZ` → 明文 `seeutomorrow`（see u tomorrow）
:::

**凯撒密码的弱点** <Src p="61–62" />：

1. <span class="hl">算法是固定的</span>——一旦被知道就全线失守；
2. <span class="hl">密钥空间太小</span>，即使随机化也一样：

::: def 移位密码（随机化的凯撒密码） @P62
**Enc**：随机选 $k \in \mathbb{N}^+$，所有字母向后移 $(k \bmod 26)$ 位；**Dec**：向前移 $(k \bmod 26)$ 位。形式化：

$$c_i = (m_i + k) \bmod 26,\qquad m_i = (c_i - k) \bmod 26$$

- 有效密钥空间大小只有 **26**；
- 用**穷举搜索 / 暴力攻击**轻松破解（试遍 26 个密钥即可）。
:::

<ShiftWheel />

::: prin 充分密钥空间原则 Sufficient Key Space Principle @P63
任何安全的加密方案都必须拥有<span class="hl">不怕穷举搜索</span>的密钥空间。

<span class="muted">注意：这是**必要条件**而非充分条件——1.2 节的单表替换就是“密钥空间够大但依然不安全”的反例。</span>
:::

<Fig src="/img/00-01/p063.jpg" cap="各机构推荐的密钥长度（keylength.com）" p="63" />

#### ROT-13：凯撒密码的特例 <Src p="64" />

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 240px;gap:18px;align-items:center">
<div>

- **Enc**：所有字母向后移 13 位；**Dec**：向后**或**向前移 13 位都行（因为 $13+13=26$，加密两次即还原）。
- 虽然**不安全**，至今仍在使用：论坛里常用它隐藏剧透、谜题答案等（www.rot13.com）。

</div>
<Fig src="/img/00-01/p064.jpg" cap="ROT13 示意（Wikipedia）" p="64" />
</div>

::: tldr
移位密码 = 密钥只有 26 种 → 穷举即破。教训：**密钥空间必须足够大**。
:::

## 1.2 单表替换密码

::: def 单表替换密码 Mono-alphabetic Substitution (MAS) @P66–68
**Enc**：随机选一个置换 $\pi: \{a,\dots,z\} \to \{A,\dots,Z\}$，把每个字母替换成它在 $\pi$ 下的像；
**Dec**：把每个字母替换成它在 $\pi^{-1}$ 下的像。

- **置换**（permutation）是集合到自身的**一一映射**；
- 一一映射保证了解密的正确性。
:::

示例 <Src p="69–71" />：选定的置换 $\pi$ 如下，密文 `KDOOFUHPSGF` 解密得 `hellocrypto`。

<PiTable />

### 1.2.1 密钥空间有多大？

::: qa 单表替换密码的密钥空间有多大？ @P72–73
等于 $\{a,\dots,z\}$ 上所有置换的个数：$\pi(a)$ 有 26 种选择；$\pi(b)$ 不能等于 $\pi(a)$，有 25 种；……；$\pi(z)$ 只剩 1 种。

$$26 \times 25 \times 24 \times \cdots \times 1 = 26! \approx 2^{88}$$
:::

::: qa $2^{88}$ 有多好？安全吗？ @P74–77
设敌手用一台 4 GHz 的计算机（≈ 每秒 $2^{32}$ 次）穷举，遍历整个密钥空间至少需要

$$2^{88} / 2^{32}\ \text{秒} \approx 2.28 \times 10^{9}\ \text{年}$$

（宇宙年龄约 $13.8 \times 10^9$ 年。）结论：**也许能抵抗穷举搜索，但对其他攻击极不安全**。

<Fig src="/img/00-01/p074.jpg" size="md" cap="一台 2015 年 6000+ 元的笔记本：i5-5200U，2.2–2.7 GHz" p="75" />
:::

### 1.2.2 致命缺陷与统计攻击

::: warn [缺陷] 同一字母的密文永远相同 @P78
<code>noclas<b class="hl">s</b>thi<b class="hl">s</b>friday → QFUOXW<b class="hl">W</b>GKV<b class="hl">W</b>NHVAXP</code>

因此**明文与密文的统计特征（字母频率）完全相同**：明文中 s 出现的次数 = 密文中 W 出现的次数。这让敌手可以实施<span class="hl">统计攻击</span>。
:::

::: qa 已知密文 QFUOXWWGKVWNHVAXP，并“恰好”知道明文里 s 出现 3 次、i 和 a 各出现 2 次。还剩多少种可能的明文？ @P79–83
W 出现 3 次 → W = s；V、X 各出现 2 次 → {i, a} 两种分配，明文形如

<code>∗∗∗∗<b>a</b>ss∗∗<b>i</b>s∗∗<b>i</b>∗<b>a</b>∗</code>　或　<code>∗∗∗∗<b>i</b>ss∗∗<b>a</b>s∗∗<b>a</b>∗<b>i</b>∗</code>

课件答案：$26\times25\times24\times23\times22\times21\times20\times19\times18\times17$，**远小于 $26!$**。

<span class="muted">（细抠：剩下 10 个不同密文字母只能映射到除 s、i、a 外的 23 个字母，严格计数为 $2\times 23\times22\times\cdots\times14$；量级结论不变。）</span>

若加密的是英文，搜索还能更快：“q 后面通常跟 u”，“t 和 e 之间很可能是 h”……
:::

实际中我们并不知道明文里每个字母的确切次数，但知道**一般英文文本中每个字母的近似频率** <Src p="84" />：

<Fig src="/img/00-01/p084.jpg" size="md" cap="英文文本的平均字母频率（e 12.7%、t 9.1%、a 8.2%、o 7.5% ……）" p="84 · P102" />

<FreqAttack />

::: qa 为什么统计攻击对单表替换有效？ @P85–86
因为密钥定义的是一个**固定映射**，并且**逐字母**作用于明文。
:::

::: qa 有更好的替代吗？ @P87–89
设法避免这种固定的逐字母映射，例如**多字母替换密码**（Poly-alphabetic Substitution）：加解密的映射作用在**明文字符块**上，如 Enc: ab→DZ, ac→TY。
:::

::: tldr
单表替换：密钥空间 $26!\approx2^{88}$ 够大，但“固定逐字母映射”保留了字母频率 → 频率分析即破。**密钥空间大 ≠ 安全**。
:::

## 1.3 维吉尼亚密码（多表移位）

先看例子 <Src p="91" />：用短语 `cafe` 作密钥（循环重复）。

<VigenereStep />

注意：明文中的两个 **l** 分别被映射成 **Q** 和 **P**；两个 **m** 分别被映射成 **R** 和 **O**——同一字母不再总是对应同一密文，单字母频率被“抹平”了。

::: def 维吉尼亚密码 Vigenère（多字母移位密码） @P92–96
给定含 $s$ 个字母的字母表 $\mathcal{A}$，密钥 $k=\{\pi_0,\dots,\pi_{m-1}\}$ 由 $\mathcal{A}$ 上的 $m$ 个**移位**组成。对明文 $x = x_0x_1\cdots$：

**Enc**：依次循环应用 $\pi_0,\dots,\pi_{m-1},\pi_0,\dots$，即 $y_i = \pi_{i \bmod m}(x_i)$；
**Dec**：依次循环应用 $\pi_0^{-1},\dots,\pi_{m-1}^{-1},\pi_0^{-1},\dots$ 作用于 $y_0, y_1,\dots$
:::

- 以法国密码学家 Blaise de Vigenère 命名，但最早由意大利密码学家 Giovan Battista Bellaso 于 **1553** 年发明；
- 三百多年间被认为**牢不可破**（首个公开的攻击由 Wilhelm Kasiski 于 **1863** 年发表）；
- 它是多字母替换密码的一个**特例**；
- 本质是**轮流使用一系列不同的凯撒密码**。

### 1.3.1 攻击维吉尼亚：两步走

::: ex [思路] 分而治之 @P97
1. **确定密钥长度 $m$**；
2. **分别破解 $m$ 个移位密码**。
:::

#### 第一步：确定密钥长度（Kasiski 法） <Src p="98" />

在密文中寻找**重复出现的片段**：同一段明文恰好对齐到同一段密钥时，会产生相同的密文，所以两次出现的**距离必是密钥长度的倍数**。下例用密钥 `beads`，两个 “LII” 相距 30，所以 $m \mid 30$。

<Fig src="/img/00-01/p098.jpg" cap="以 “beads” 为密钥的维吉尼亚密码" p="98" />

<KasiskiSearch />

#### 第二步：破解 m 个移位密码 <Src p="99" />

对每个候选 $m$，把密文按位置模 $m$ 分成 $m$ 组，每组都是同一个移位密码加密的，**各自独立**用统计攻击破解：

$$
\begin{aligned}
&y_0,\ y_m,\ y_{2m},\ \dots\\
&y_1,\ y_{m+1},\ y_{2m+1},\ \dots\\
&\qquad\vdots\\
&y_{m-1},\ y_{2m-1},\ \dots
\end{aligned}
$$

## 1.4 易于自动化的统计攻击

要让计算机自动攻击，需要一个**量化指标**来衡量“某个猜测有多对” <Src p="101–104" />。借助英文字母频率表：

::: def [方法] 用 Ij 找移位量
设 $p_i$ 为正常英文中第 $i$ 个字母的频率（$0\le i\le 25$），由频率表可知

$$\sum_{i=0}^{25} p_i^2 \approx 0.065$$

设 $q_i$ 为密文中第 $i$ 个字母的频率：

$$q_i = \frac{\text{密文中第 } i \text{ 个字母出现的次数}}{\text{密文长度}}$$

对所有 $j \in \{0,\dots,25\}$ 计算

$$I_j = \sum_{i=0}^{25} p_i \cdot q_{i+j}$$

取 <span class="hl">$I_j$ 最接近 0.065</span> 的 $j$ 作为密钥。
:::

::: ex [直觉] 为什么是 0.065？
若猜对了密钥 $j=k$，则 $q_{i+k}\approx p_i$，于是 $I_k \approx \sum p_i^2 \approx 0.065$；猜错时相当于把两个“错位”的分布做内积，通常只有 0.038 左右。<span class="muted">（补充说明，下标均取 mod 26）</span>
:::

<IjAttack />

::: tldr
维吉尼亚 = $m$ 个移位密码轮流用。攻击：Kasiski 定 $m$ → 分组 → 每组用 $I_j\approx0.065$ 自动定移位。
:::

## 1.5 古典密码 vs 现代密码学

<div class="two-col" style="display:grid;grid-template-columns:minmax(0,1fr) 260px;gap:18px;align-items:center">
<div>

**古典密码** <Src p="107" />：

- 设计更像**艺术**而非科学；
- 很多古典密码的安全性严重依赖于**隐藏细节**（例如怎么加密）；
- <span class="hl">所有历史上的古典密码都已被证明不安全。</span>

</div>
<Fig src="/img/00-01/p107.webp" cap="密码棒（scytale），古希腊斯巴达的加密方法" p="107" />
</div>

**现代密码学** <Src p="108–111" />：过去几十年里，密码学发展成了一门**科学**。

- 终极目标：**严格证明**某个构造是安全的；
- 强调**安全定义**；
- 强调关于某些数学问题**算法困难性的（未经证明的）假设**。

::: exam 一句话区分古典与现代
“对**定义、假设与证明**的强调，把现代密码学与古典密码学区分开来。”
:::

#### 原则 1：形式化定义 <Src p="113–122" />

现代密码学的关键贡献之一：认识到**形式化的安全定义**对于正确设计、研究、评估和使用密码原语是必不可少的。要形式化地定义安全，必须先搞清楚两件事：

我们面对的是什么样的敌手？
:::
::::

以“安全加密”为例，**安全目标**应该是什么？下面四种说法逐级加强——看看前三种为什么不够：

**威胁模型**：敌手的能力由弱到强 <Src p="119–122" />：

| 攻击模型 | 敌手能力 |
|---|---|

| 已知明文攻击 <span class="en">Known-plaintext</span> | 在攻击其他密文之前，可以知道一些明文/密文对。 |

#### 原则 2：精确假设 <Src p="123–124" />

- 大多数现代密码构造**无法无条件地**被证明安全；
- 证明往往需要解决计算复杂性理论中至今远未解决的问题（如 P vs NP）；
- 例：在不知道 $p,q$ 的情况下，分解 $N = p \times q$（$p,q$ 为大素数）被**假设**是困难的。

#### 原则 3：安全性证明 <Src p="125" />

原则 1 和 2 使我们能够**严格证明**：在一定假设下，某个构造满足给定的定义。这样的证明提供了“**没有敌手能成功**”的铁一般的保证。

### 1.5.2 可证明安全 vs 现实安全

::: warn 可证明安全 ≠ 现实安全 @P127–128
一个方案的可证明安全**不一定**意味着它在现实中安全，例如：

- 安全保证与实际需要不匹配；
- 威胁模型没有刻画敌手的真实能力；
- 假设被证明是错的。

这种差距**不是缺点**：攻击者只需盯住定义或底层假设；反过来，我们也可以改进安全定义使其更贴近现实，并持续研究假设。
:::

## 1.6 Kerckhoffs 原则

### 1.6.1 通过隐藏实现安全

这正是大多数古典密码赖以设计、并被认为安全的想法（security through obscurity）<Src p="131" />：把加密算法藏起来就能提升安全性吗？用“自研”算法更好吗？

<Fig src="/img/00-01/p131.jpg" size="md" cap="xkcd “Code Talkers”：用纳瓦霍语的“零”和“一”传比特流——藏的只是编码方式" p="131" />

::: prin Kerckhoffs 原则（柯克霍夫原则） @P132–133
“加密方法不必保密，它落入敌人手中也不应造成任何不便。”——Auguste Kerckhoffs，1883 年（荷兰，1835–1903）

- 即使除密钥之外的**所有细节**都被敌手知道，也必须是安全的；
- 安全性**只依赖于密钥的保密**，而不依赖于加密方法的保密。
:::

::: qa 讨论：你支持哪一种——“隐藏算法”还是 Kerckhoffs 原则？ @P134–135
课件建议阅读教材第 1.2 节看作者的观点。要点：密钥比算法**容易保密**（短）、**容易更换**（泄露后换个密钥即可，换算法代价巨大）；多用户场景下大家可以用同一个公开算法、各自不同的密钥；公开算法还能接受公众审查，更早发现漏洞，并便于标准化。
:::
